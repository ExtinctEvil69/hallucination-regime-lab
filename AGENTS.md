# AGENTS.md: instruction manual for coding agents

This file tells any coding agent (or human contributor) how to work on this repository safely. Read it
before changing anything. `README.md` describes the research itself.

## 1. What this project is

The project is a Bayesian study of hallucination **onset** in six-turn conversations about fictional
dossiers. A local LLM (Qwen3-4B-Instruct via Ollama) answers. Answers are graded deterministically
against gold records. Hidden Markov models (EM, FFBS-Gibbs, a covariate-dependent HMM) are compared with
a matched static detector. The project also includes a randomised correction experiment, a clinical
"guard" application, red-team attacks and an interactive UI.

## 2. Setup

```sh
python3 -m pip install "numpy>=1.26" "scipy>=1.11" matplotlib pytest
python3 verify.py                       # all offline tests must pass before and after any change
```

Live collection and the UI's live mode need Ollama with `qwen3:4b-instruct` (`ollama pull qwen3:4b-instruct`).
Everything else, including replays, results and reports, works offline.

## 5. Hard rules (never break these)

1. **No label leakage.** Gold answers and grades must never reach detector inputs
   (`features/extract.py`, `usecase/guard.py`). The live guard may use only the visible chart and the question.
2. **Splits are fixed and dataset-bound** (`runs/<dataset>/splits.json`). Never re-split an evaluated dataset.
   Nothing may be tuned on `test`. Thresholds and state mappings are chosen on `val` only.
3. **Experiment records are immutable.** Never edit, delete or regenerate files in `runs/*/raw|gold|grades`.
   Collection must fail closed rather than overwrite.
4. **No hand-typed numbers.** All result text (README headline, `results/results.md`, blueprint and draft1
   numbers) is generated by `make_report.py` / `draft1/make_numbers.py` from saved artifacts.
5. **Do not change what is measured after seeing results.** That includes endpoints, risk sets, splits,
   thresholds, label definitions and eligibility. Any such change is a new, clearly labelled
   *exploratory* analysis added next to the locked one, never a replacement.
6. **Never weaken a test, canary or diagnostic gate to make it pass.** The convergence gate is
   R-hat ≤ 1.01 and bulk ESS ≥ 400. Models that fail are reported as NONCONVERGED.
7. **Synthetic results are labelled `synthetic: true`.** All patients, names and codes are fictional.
   Never add real personal or medical data.
8. **No secrets.** Never commit API keys, tokens, credentials, `.env` files or local absolute paths.

## 6. How to make a change

1. Run `python3 verify.py` first and keep it green.
2. Reproduce the problem with a minimal failing test, add it under `tests/`, then fix the code.
3. Keep changes narrow and target-preserving: the same priors, configuration and endpoints, unless the change is
   explicitly a new exploratory analysis.
4. If a change affects saved results, do not overwrite them. Re-run into a new versioned directory, mark
   the old outputs as affected, and regenerate reports through the CLIs.
5. Re-run `python3 verify.py`, `python3 make_report.py`, and rebuild any PDF or slides whose inputs changed.
6. Describe what changed, why, which tests cover it, and whether any reported number moved.

## 7. Versioned behaviour you must preserve

- **Grader:** `GRADER_VERSION = "1"` is the locked default. Grader v2 (negations, contradictions, extra
  claims → pending) is opt-in only (`version="2"`).
- **Reference resolution in the live guard:** `coref="v1"` is the locked default. `coref="v2"` (full name →
  surname + year → bounded coreference → unresolved) is opt-in and selectable in the UI.
- **Bayesian outputs:** the current results are in `results/v2_samplerfix/`. Earlier outputs in
  `results/<study>/` are kept for provenance and marked `AFFECTED_sampler_fix.json`.

## 8. Known limitations (report them; do not hide them)

- The covariate model M4 and the two-component Bayesian fits do not pass the convergence gate. The
  exploratory single-component M3 passes. A sampler redesign is future work.
- The state posterior is not a calibrated error probability; strict false-stop alarms never fire.
- One model checkpoint, a fictional short-code task, top-20 entropy proxy, a small clinical test split.
